Starter template for exporting Org-mode files to HTML with a customized
readtheorg theme. Copy this folder wherever a new note needs styled HTML
export.

Related pages: [[./index.org][Index]] | [[./template.org][Template]]

* Structure

| Path                                        | Purpose                                             |
|----------------------------------------------+------------------------------------------------------|
| =template.org=                              | Starter file: standard preamble + SETUPFILE include |
| =theme-readtheorg.setup=                    | HTML_HEAD include: wires up all CSS/JS below        |
| =org-themes/lib/js/=                        | jquery, bootstrap, stickytableheaders (theme deps)  |
| =org-themes/readtheorg_theme/css/=          | =htmlize.css= (syntax colors), =readtheorg.css= (layout), =stacked-nav.css= (pane columns) |
| =org-themes/readtheorg_theme/js/=           | =readtheorg.js= (sidebar + per-page content passes), =stacked-nav.js= (stacked navigation) |
| =Makefile=                                  | =make export= builds all =.org= files into =html/=  |
| =githooks/pre-commit=                       | Runs =make export= and stages =html/= before every commit; enable with =make install-hooks= |
| =html/=                                     | Generated output: exported HTML + a copy of =org-themes/= alongside it |
| =wrangler.toml=                             | Tells Cloudflare's Worker build to serve static assets from =html/= |

=html/= is generated output — regenerate it with =make export=, don't
hand-edit anything inside it.

* Customizations vs. the stock readtheorg theme

- *Roam-style stacked navigation*: following a link to another page in this
  site opens it as a new column to the right instead of replacing the page,
  so you keep the page you came from in view. At most three columns are open
  at once -- opening a fourth drops the leftmost -- and each column has a
  close button in its title bar. The left sidebar always shows the table of
  contents of whichever column has focus, and the open set is mirrored into
  the URL as =?stack=a.html,b.html=, so reloading or sharing that link
  restores the same columns and Back pops one off. Below 768px the columns
  become full-width and scroll-snap, so open pages are one swipe apart
  (=stacked-nav.js= / =stacked-nav.css=).

  This needs the site to be *served over http(s)*, because mounting a page
  into a column fetches it and browsers refuse =fetch()= on =file://= URLs.
  Opened straight off disk the theme notices and stays out of the way: one
  page at a time, links navigating normally. See [[*Viewing the export locally][Viewing the export locally]].
- *Collapsible TOC sidebar*: a hamburger button toggles the left
  table-of-contents; state persists per-browser via =localStorage=
  (=readtheorg.css= / =readtheorg.js=).
- *Legible code blocks*: =pre.src=/=.codeblock= always render with a dark
  (Monokai-matching) background, since Org's exported syntax-highlight
  colors are baked in as inline styles tuned for a dark background
  (=readtheorg.css=).
- *Page-wide dark mode toggle*: =template.org= embeds the [[https://github.com/sun0225SUN/darkmode-js][darkmode-js]]
  CDN widget (bottom-right button) for toggling the whole page between
  light/dark.

* Usage

1. Copy this folder to the new note's location.
2. Rename/edit =template.org= (update =#+TITLE=, write content).
3. Export to HTML:
   - All files at once: =make export= — finds every =.org= file (skipping
     =org-themes/=), exports each with Emacs, and collects the results plus
     a copy of =org-themes/= into =html/= so the CSS/JS paths still resolve.
   - =make clean= removes =html/=.
   - A single file, without the Makefile: =C-c C-e h h= in Emacs, or from
     the shell:
     #+begin_src sh
       emacs --batch template.org -f org-html-export-to-html
     #+end_src
4. Optional: =make install-hooks= points git at =githooks/=, so every commit
   runs =make export= and stages =html/= automatically — no more forgetting
   to regenerate it before pushing.

** Viewing the export locally

Double-clicking =html/index.html= opens it over =file://=, where the
stacked-column navigation is switched off (see above) — everything else
works, but links replace the page instead of opening a column beside it. To
see the site as it deploys, serve the directory over http:

#+begin_src sh
  cd html && python3 -m http.server 8000
#+end_src

then open =http://localhost:8000/=.

All paths in =theme-readtheorg.setup= are relative to the =.org= file, so
keep the =org-themes/= folder alongside it when exporting by hand.

* Deployment (Cloudflare Workers Git integration + GitHub SSO)

The Cloudflare dashboard's "Create a Worker" → "Import a repository" flow
deploys straight from GitHub — no separate CI config in this repo. Point
it at =lendkhoa/org-template= and use:

- *Build command*: leave empty. Cloudflare's build container runs as a
  non-root user with no =apt-get= access, so Emacs can't be installed
  there — =make export= has to happen locally instead (see Usage above).
- *Deploy command*: =npx wrangler deploy= (default). Reads =wrangler.toml=
  at the repo root, which declares =html/= as the static assets
  directory and =org-template= as the Worker/project name.

Because there's no build step, =html/= must be regenerated and *committed*
locally (=make export=, then =git add html/=) before pushing — Cloudflare
only deploys whatever is already checked into =html/= at the pushed
commit. Every push to the connected branch (=main=) triggers a redeploy
of that content — no GitHub Actions workflow involved.

** One-time Cloudflare setup

1. *Run the wizard* (Workers & Pages → Create → Import a repository),
   selecting =lendkhoa/org-template= and entering the build/deploy
   commands above.
2. *Protect with Cloudflare Access*: the wizard has a "Protect with
   Cloudflare Access" toggle — enable it. If prompted, pick a Zero Trust
   team name (free tier covers small teams).
3. *Add GitHub as an identity provider* (Zero Trust → Settings →
   Authentication → Login methods → Add → GitHub): create a GitHub OAuth
   App (GitHub → Settings → Developer settings → OAuth Apps → New OAuth
   App) using the Authorization callback URL Cloudflare shows on this
   screen, then paste the Client ID/Secret back into Cloudflare.
4. *Set the Access policy* on the application Cloudflare created for
   this project (Zero Trust → Access → Applications) to GitHub login
   only, with an Allow rule limited to the specific GitHub identities
   (or GitHub org) that should have access.

Once configured, every push to =main= redeploys automatically; visiting
the site prompts a GitHub login and only approved accounts get through.
